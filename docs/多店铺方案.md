# 多店铺方案（焕捷 + 爱睿特）

2026-11-04 起草，依据用户两轮反馈。本文是实施依据；和 `父体绑定实施方案.md` 冲突时以本文为准（被改掉的条目实施时在那边的变更记录里注明）。

---

## 一、已经定下的事

| 事项 | 决定 |
| --- | --- |
| 店铺怎么选 | 顶栏「店铺」下拉。**一批只属于一个店铺**：队列里有图（含暂停、需处理）时下拉锁住，提示「先清空队列再换店铺」；清空后选的店铺用于下一批 |
| 输出文件夹 | 不按店铺分，结构不变（`主图生成-日期/品类/主图/…`）。批次记录里存店铺，SKU 前缀本身就能看出店铺 |
| 专属号 | 子体 SKU 的专属号**默认 0**，不再是设置里的固定值。图生完后在「识别信息」用「改专属号」一次改掉这一批所有 SKU（见第五节） |
| 父体专属号 | **父体 SKU 不加专属号**，两个店铺都一样（原来焕捷建议新建是 `HJ-cn-yklgj5-…`，以后是 `HJ-cn-yklgj-…`） |
| 新父体 SKU | `店铺缩写-材质编码-主题`，前缀参考店铺里同类父体，`cn-` 表示中国发货，跟着参考的前缀走 |
| 子体 SKU 格式 | 统一 `店铺缩写-材质编码 + 年份末位 + 组别 + 月日 + 专属号 + 当天序号`，生图一开始就定，文件名用它（用户选 A）。不用「父体SKU-日期码」那种 |
| 子体材质编码 | 先用模版库品类的编码；第 6 步匹配到父体后，**跟着这个父体下其他子体的编码走**（如父体下都是 `HJ-cn-tyntyt…` 就改成 `cn-tyntyt`），看不出来时用 SP-API 查同类商品判断（见第六节） |
| 变体名 | 已有父体：参考这个父体下其他子体往下排（现有逻辑不变）。建议新建的父体：参考同品类最近父体里用得最多的写法，没有可参考的用 `Style01` |
| 爱睿特父体来源 | 没有飞书父体表，用 SP-API 扫描店铺里的父体（第四节） |
| 焕捷父体来源 | 继续用飞书父体表 |
| 品类 ↔ 店铺父体 | 按亚马逊商品类型（毛毯 → BLANKET），模版库每个品类加一项「店铺商品类型」 |
| 旧格式父体 | 日期码父体（`mtfl760820700-P`，SKU 里没主题）也参与匹配，AI 看商品标题 |
| 站点 | 只用美国站 |
| 「地区标识」 | 改叫「组别」（飞书 SKU 规则表：7 = 深圳团队），值不变，两个店铺实测都是 7 |

### 实测依据（2026-11-04，只读）

- 爱睿特：亚马逊店铺名 ClassicOnceMore，品牌 LOPHAW，美国站 693 个商品（父体 102、子体 578、单品 13），店铺缩写 `ART`。
- 飞书「亚马逊sku目录」：店铺编码（ART = 爱睿特、HJ = 焕捷 等 7 个）、组别（6 康康、1 左一、3 光合、9 清和、8 淮安团队、7 深圳团队）、38 种产品编码（`cn-` = 中国发货）。
- 材质编码两个店铺基本通用，但店里实际用法和规则表不完全一致：庭院灯规则表 `cn-tyntyt`，焕捷多数 `cn-tyntyd`、爱睿特 `tyntyt`；毛毯 `mtfl` 和 `cn-mtfl` 并存。所以子体编码要跟着父体走（第六节）。
- 爱睿特父体两代：10-22 以前是日期码（`ART-cn-yklgj670921700-P`），10-26 以后是 `ART-cn-yklgj-cookie` 这种主题式，都不带专属号。
- **SP-API 搜索最多只返回 1000 条**：焕捷 1365 个商品只拿到 1000 个。实测按创建日期分段（`createdAfter / createdBefore`）能绕开，每段不超过 1000 条。

## 二、数据

### 2.1 设置：店铺档案

```ts
settings.stores: {
  id: string                    // 'hj'、'art'，内部用，不显示
  name: string                  // 焕捷、爱睿特
  abbr: string                  // HJ、ART（SKU 前缀）
  parentSource: 'feishu' | 'store'
  spapi: { sellerId; clientId; clientSecret; refreshToken; marketplaceId; endpoint; tokenUrl }   // 每个店铺一份，打码显示
  feishu: { sheetUrl; recentUrls; tabs }   // 只有 parentSource = 'feishu' 用
}[]
settings.currentStoreId: string
settings.sku.group: string      // 原 sku.region，改名「组别」，默认 '7'，所有店铺共用
```

- **迁移**：旧设置自动变成一个「焕捷」店铺（`parent.spapi` → `stores[0].spapi`，`sku.store` → `abbr`，`parent.sheetUrl / recentUrls / tabs` → `stores[0].feishu`），再加一个空的「爱睿特」（`ART`、`store` 来源）。迁移前备份 `settings.json`。
- 飞书 App ID / Secret、识别父体开关、把握阈值仍是全局的。
- `parent.creatorMark` 去掉（专属号改到批次上，父体不用）。
- 凭证导入、测试连接都按店铺做：导入的文字只写进当前编辑的那个店铺，导入后只显示末 4 位，两个店铺的凭证互不覆盖。

### 2.2 批次和任务

- `data/batch.json` 加 `storeId`、`mark`（专属号，默认 `'0'`）。开新批次时取当前店铺，`mark` 回到 `'0'`。
- `job.storeId`：加进队列时从批次取，之后不变。第 6 步、SKU、查重都只看任务自己的 `storeId`。旧任务、旧批次按焕捷处理。
- `job.skuNote`：SKU 被第 6 步改过材质编码时记一句原因，详情里显示。

### 2.3 模版库

- `Category.productTypes: string[]`，默认 `[]`：这个品类对应的亚马逊商品类型（如 `['BLANKET']`），`store` 来源的店铺用它挑候选父体。
- 下拉选项来自当前店铺的扫描结果；推荐项是「SKU 里含这个品类材质编码的商品」最常见的类型。
- 不升库版本；导出、导入的 zip 带上它。`parentTab` 照旧，只有飞书来源的店铺用。

## 三、店铺隔离

| 东西 | 怎么隔离 |
| --- | --- |
| 凭证 | 每个店铺一份 |
| SP-API access token | 每个店铺一个客户端，各自缓存（现在是一个全局缓存，改了凭证才重换） |
| 店铺商品快照 | 按店铺缓存 |
| 子体 SKU 当天序号 | 序号键本来就含店铺缩写，另加店铺 ID 防同名缩写 |
| 变体占号 | 按批次文件夹记，一批只属一个店铺，天然隔离 |
| 第 6 步暂停 | 暂停原因带上店铺名；换店铺时清掉 |
| 飞书父体表缓存 | 按链接，只有焕捷用 |
| 模版库 | 模版、提示词、白底图共用；材质编码共用（店铺之间的差异由第六节跟父体处理） |

## 四、店铺商品快照（`parent/storeIndex.ts`）

- 用 Listings 搜索翻完店铺所有商品（`includedData=summaries,relationships,attributes`）。超过 300 条时按创建日期二分成多段，每段不到 300 条（也一定不到 1000 的上限），3 段同时翻。（2026-11-04 改：原来是「超过 1000 条才分段、一段一段翻」，实测焕捷要 90 秒，改后 35 秒，爱睿特 47 秒 → 23 秒）
- 记下每个商品：SKU、ASIN、标题、商品类型、创建日期、父体 / 子体 / 单品、父体的变体主题和子体 SKU、子体的变体属性值。
- 父体主题：SKU 是 `前缀-主题` 式（主题里有字母、不是 `P`、`F`、`H` 这类单字母尾巴）就从 SKU 拆；日期码父体主题为空，靠标题。
- 缓存 10 分钟；同一时间只扫一次，并发的请求共用。超过 10 分钟、不到 2 小时的快照先用着，同时后台重扫（第 6 步不用等几十秒）；没有快照、超过 2 小时、「重新扫描」和改专属号查重时等扫完。设置里店铺卡片有「重新扫描」，显示上次扫描时间和商品数。开着识别父体时，启动后先在后台扫一遍当前店铺。
- 用途：
  1. 爱睿特第 6 步的候选父体；
  2. 建议新父体的前缀和变体名起始写法；
  3. 子体材质编码判断；
  4. 发 SKU 和改专属号时查重。
- 选中父体后，查它的子体仍然**现查**（不用快照），保证刚建的子体能算进去。

## 五、子体 SKU 和「改专属号」

**发 SKU（第 ① 步定下品类时，和现在一样）**

- 格式是 `{店铺缩写}-{材质编码}{年份末位}{组别}{月日}{专属号}{序号}`，专属号用批次的 `mark`（默认 0），例如 `ART-mtfl671104001`。
- 跳过这些已占用的号：队列里已有的、输出文件夹里已有的、店铺快照里已有的。快照只在有缓存时查，不为发号去等扫描；10 分钟内别人刚建的号可能查不到，改专属号时会再查一次。

**改专属号（「识别信息」页顶部）**

1. 显示「专属号：0」和「改专属号」按钮。点开后输入新号（字母或数字，1～10 位），先列出预览：每行「旧 SKU → 新 SKU」。
2. 预览前强制重新扫描店铺，并查输出文件夹。新 SKU 已经存在的标红，有冲突就不能应用，提示换一个号。
3. 应用后：
   - 这一批所有图的 SKU 只换专属号那一位，序号不变。范围包括还在队列里的图，以及已经「清除已完成」但还在 CSV 里的行。
   - 主图、素材图、空白图三个文件改名，CSV 重写。
   - 批次 `mark` 改成新号，之后这一批再加的图也用它。
4. 正在生成的图先等它这一步写完再改（改名时锁住这张图的输出）；任意一个文件改名失败就整批回滚。
5. 不影响父体、变体名和占号。

---

## 六、子体材质编码跟着父体走（第 6 步末尾）

第 6 步定下父体后，按下面的顺序找编码，找到就停：

1. **已有父体**：从它的子体 SKU（刚现查的）里拆编码。去掉 `店铺缩写-`，取开头的 `(cn-)?字母`；遇到数字或 `-主题` 停。比如 `ART-cn-yklgj-Farm-671031701` 拆出 `cn-yklgj`，`HJ-cn-tyntyt670720204` 拆出 `cn-tyntyt`。取出现最多的；票数一样时取最新子体的。
2. 子体拆不出来，就拆父体 SKU 本身（`ART-cn-yklgj-memory` → `cn-yklgj`，`mtfl760820700-P` → `mtfl`）。
3. **建议新建的父体**：用新父体前缀里的编码，保证父子一致。
4. 还拆不出来（如 `Z9-PX7O-E911` 这种随机 SKU）：用店铺快照里同一商品类型最近 60 天新建商品最常见的编码。
5. 都没有：保持模版库的编码。

拿到的编码和这张图现在 SKU 里的不一样时，按新编码重新发一个号（新前缀下取当天序号，旧号不收回），三个输出文件改名、CSV 重写，`job.skuNote` 记下「按父体下子体改成 cn-tyntyt（原 cn-tyntyd）」。改名和第五节共用一套逻辑。

> 和用户说的「调 AI 接口看」不同的地方：SKU 结构是固定的，程序按规则拆就能准确拿到编码，不花额度、结果稳定；AI 对随机 SKU 也看不出编码。所以这里不调 AI，看不出来时按第 4 条查店铺。如果用户坚持要 AI，可以在第 4 条前加一次 AI 判断。

## 七、第 6 步按店铺

- 开关、缺设置判断按任务店铺：飞书来源要链接 + 飞书应用 + 店铺凭证；店铺来源只要店铺凭证。缺了照旧跳过，写明缺哪一项。

**店铺来源（爱睿特）**

1. 候选：快照里商品类型属于品类 `productTypes` 的父体，新建的排前面，最多 300 个。品类没设商品类型 → `none`，提示「去模版库给『毛毯』选店铺商品类型」。
2. 发给 AI 的清单每行：编号、主题（可能为空）、父体 SKU、商品标题。系统提示词的主题样例取主题式父体的主题。
3. 选中后照旧现查子体、推算命名、占号；然后按第六节定子体编码。

**建议新父体（两个店铺都改）**

- 前缀：同品类的主题式父体（飞书表的行或快照）里最多的前缀，最后一段末尾的数字去掉（不加专属号）。`HJ-cn-yklgj5` 会变成 `HJ-cn-yklgj`。
- 店铺来源只用主题式父体统计，日期码父体拆不出前缀，跳过。
- 查重：同品类候选、整个店铺快照、现查一次 SP-API。
- 第一个变体名：同品类最近 10 个有子体的父体里最常见的写法，比如 `Style##`、两位数，就从 `Style01` 起；没有可参考的用 `Style01`。焕捷同样按店铺快照算，不再固定 `Design 01`。

## 八、界面

- **顶栏**：「店铺」下拉，显示店铺名。队列有图时变灰，悬停提示「先清空队列再换店铺」。
- **设置「店铺」组**：每个店铺一张卡片，内容是名称、缩写、父体来源、SP-API 凭证（导入 / 四项打码 / 测试连接）、快照（上次扫描时间、商品数、重新扫描），飞书来源的店铺还有父体表链接。
  - 可以新增店铺；删除要连点两次，当前店铺不能删。
  - 「组别」放在「SKU 命名」里，原「专属号」输入框去掉。
- **识别信息**：顶部显示「店铺：爱睿特 · 专属号：0 · 改专属号」。SKU 被第六节改过的，SKU 旁边加小字提示。
- **详情第 6 步**：显示用的是哪个店铺、候选来自飞书表还是店铺扫描；店铺来源时候选显示商品标题。
- **模版库品类**：加「店铺商品类型」多选；「父体表标签页」只在当前店铺是飞书来源时显示。

## 十一、变更记录

### 2026-11-04 · 起草

- 用户反馈：一批一个店铺、生图过程中不能换；输出不按店铺分；专属号默认 0、生完后可统一改；父体不加专属号；`cn` 表示中国发货，前缀参考店铺父体；变体名参考父体下其他子体；子体编码灵活，跟着父体下子体走，看不出来时用 SP-API 判断。
- 实测发现 SP-API 搜索 1000 条上限，按日期分段解决。
- 第六节没有用 AI 判断编码，原因写在第六节，用户确认方案（「没啥问题」）。

### 2026-11-04 · 第 1 段「店铺档案」完成

- **设置结构**：`settings.stores[]`（id / name / abbr / parentSource / spapi / feishu{sheetUrl, recentUrls, tabs}）+ `currentStoreId`。`parent` 只剩 enabled / threshold / creatorMark / feishu（应用身份，全局）；`sku` 只剩 `group`（原 region）。
- **迁移**：读到没有 `stores` 的旧设置时，原来的 spapi、父体表、`sku.store` 归焕捷（`hj`，飞书来源），另加空的爱睿特（`art`，店铺来源），当前店铺是焕捷。迁移前复制一份 `settings.v1-<时间>.json`，迁移结果马上写回。用真实设置文件的副本验证过：焕捷凭证、父体表、14 个标签页都在。
- **接口**（替换原来的 `/settings/parent/test`、`/settings/spapi/import`、`/settings/spapi/test`）：
  - `POST /stores`、`PATCH /stores/:id`、`DELETE /stores/:id`：缩写不能和别的店铺重（不分大小写），当前店铺不能删；接口地址（endpoint / tokenUrl）改不了。
  - `POST /stores/:id/feishu/test`：读这个店铺的父体表，用过的链接和标签页记在这个店铺下。

### 2026-11-04 · 第 2 段「店铺商品快照」

- `parent/skuParse.ts`：`materialCode`（SKU → 材质编码）、`themeParent`（主题式父体 → 前缀不带专属号 + 主题）、`majorityCode`（一组 SKU 里最多的编码）。
  - 真实数据核对：焕捷 1000 个（当时还是单次扫描）全部拆得出编码；爱睿特 693 个里 15 个拆不出（`Z9-PX7O-E911` 这类随机 SKU、`51061202-black-m`），按第六节第 4 条兜底。
  - **新发现**：编码前面可能带两个大写字母，`HJ-HBxkfb671030404`、`HJ-SBlbh…`、`HJ-HBfbxk…`、`ART-HB-xkfb671014701`（焕捷子体里 62 个，父体里没有）。先当成编码的一部分原样保留。2026-11-04 用户确认：HB = 横版、SB = 竖版。还有 `HJ-xkfb-2607-Wrestling`（编码后多一段数字）、`HJ- HBfbxk…`（横杠后多一个空格）也能拆。
- `parent/storeIndex.ts`：`scanStore`（分段、并发、按 SKU 去重、按创建时间排）和 `StoreIndex`（按店铺缓存，缓存键含缩写 / 店铺 ID / 站点，换了就作废）。还没有子体但有变体主题的商品算父体。
- 实测（只读）：爱睿特 696 个（父体 102，其中主题式 20）23 秒；焕捷 1365 个（父体 232，主题式 231）35 秒，分段后一个不漏、不重复。
- 接口：`GET /stores/:id/scan`（只看缓存，不发请求）、`POST /stores/:id/scan`（重新扫描）；删店铺时丢掉它的快照。店铺卡片显示扫描时间、商品数、父体数和「重新扫描」。
- SP-API 客户端：加 `search`；缓存的 access token 被 401 / 403 时先换一次新 token 再试一次，还不行才算凭证错误（测试里发现 token 提前作废会被误报成凭证错）。
- **审查后补的规则**（2026-11-04）：
  - 翻页按创建时间从旧到新排（`sortBy=createdDate&sortOrder=ASC`）。实测接口默认按最后修改时间倒序，扫描的几十秒里有商品改了价格或库存就会挪位置，落在页边界上的那条会被漏掉。
  - 各段总数加起来少于全店总数（没有创建时间、早于 2015 年），或者某段 51 页还没翻完，就标记「快照不全」；分段最小到 1 分钟。同时在飞的请求不超过 3 个（看总数的也算）；有一个请求失败，其他段不再发新请求。
  - 正在扫的时候「重新扫描」，或者途中换了凭证：排在它后面再扫一次，不拿它的结果；多个强制重扫共用这一次。扫的途中删了店铺，扫完不写回缓存。后台重扫失败后 1 分钟内不在后台重试。
  - 并发请求同时拿着作废的 token：每个都换新 token 再试一次（原来只有第一个会重试，其他的被误报成凭证错误）。
  - 判断父体 / 子体先看 `parentage_level`，没有这个属性时再看子体 SKU 和变体主题。
  - 编码前的标记只认 HB / SB（在爱睿特里看到 `HJ-mtfl…` 不会把 `HJ` 当成标记）；`-P2`、`-PH` 这种尾巴也当日期码父体。
  - 设置里店铺卡片碰上后台正在扫，每 3 秒刷新一次状态，扫完按钮恢复。
  - 遗留：`AbortSignal` 还没有接进扫描（现在没有调用方用），第 3、4 段接第 6 步时再补。

### 2026-11-04 · 第 3 段「批次和任务带店铺、改专属号」

- **款式标记**（用户确认 HB = 横版、SB = 竖版，选「按款式自动加」）：模版库每个款式加「SKU 款式标记」（`Style.skuMark`，1～4 个字母，存大写，空 = 不加），放在材质缩写前面、`cn-` 后面：帆布画横版 `HJ-HBxkfb671104001`，`cn-xkfb` → `cn-HBxkfb`。旧库读入时补 null，不升版本。第 6 步匹配到父体后，如果父体下子体都不带标记，第 4 段按第六节改成和它们一样。
- **一批一个店铺**：每批记 `data/batches/<文件夹>.meta.json`（`storeId`、`mark`），改版前的批次没有这个文件，按焕捷、专属号 0。`BatchFolders.current()` 发现开着的批次不是当前店铺时开新文件夹。
  - 换店铺：`POST /stores/:id/use`，队列里有图返回 409「先清空队列」；换了之后关掉当前批次，开着识别父体就在后台预先扫一遍新店铺。顶栏「店铺」下拉在队列有图时变灰。
  - 删店铺：队列里还有它的图时 409。
  - 任务加 `storeId`（入队时取批次的店铺，之后不变；旧任务按焕捷）、`skuMeta`（SKU 的三截：专属号前面、专属号、序号）。
- **发 SKU**：店铺缩写取任务所属店铺；专属号取这一批的（默认 0）；跳过队列里别的图、输出文件夹里已有的、店铺快照里已有的（只看已扫好的快照，不等扫描）。
- **改专属号**：`GET /batch`（这一批的店铺、专属号）、`POST /batch/mark { mark, apply }`。
  - 范围：队列里这一批的图 + 已经移出队列、CSV 里还有的行（CSV 保存行从这一段起记 `skuMeta`）。没有 `skuMeta` 的 SKU（改版前发的、被改过的）列为「不改」并写原因。
  - 先强制重扫店铺（没填凭证时只查本地，界面写明；扫描失败不改），新 SKU 在店里、队列里别的图、输出文件夹里已有，或者批内重名，算冲突，有冲突不改。
  - 这一批有图正在生成时 409；改名期间这一批的图不派发；文件改名有一个失败就把已经改的改回去。
  - 改完：三类文件改名、队列里的任务和 CSV 保存行换新 SKU、批次专属号改成新号、重写 CSV；之后发号按新专属号，跳过已占的。
  - 界面：「识别信息」上方显示「店铺：爱睿特 · 专属号：0」和「改专属号」，先预览（旧 → 新、冲突标红），没冲突才能确认。
- **父体不加专属号**（原计划第 4 段，提前做）：`settings.parent.creatorMark` 去掉（旧设置文件里有也忽略），建议新建父体的前缀去掉末尾数字（`HJ-cn-yklgj5` → `HJ-cn-yklgj`）。设置里的「专属号」输入框去掉，改成提示去「识别信息」改。
- **审查后补的规则**（2026-11-04）：
  - **跨批次不重号**（审查发现会重号，阻止提交）：同一天两批都改成同一个专属号，原来只看当前这一批，第二批再加图会发出和第一批一样的 SKU。改成 `data/sku.json` 记最近 7 天发过的号（计数器里 1～n 的号，加上改专属号改出来的号），发号和改专属号都对照它，不分批次。每个 SKU 记下以前用过的名字（`skuMeta.was`），改回自己以前的号不算冲突。旧格式的 `sku.json` 能直接读。
  - 改专属号和单张图的操作互斥：这一批有图在删除、重做、仍然使用、手动换父体时不改；改的时候这些操作返回 409。
  - 改完文件名之后的几步（队列任务、CSV 保存行、批次专属号、CSV）放进 CSV 锁里做，保存行现读；任何一步失败，任务、保存行、专属号、文件名全部改回原样。改名不覆盖已有文件；只差大小写时先改成临时名。
  - 加图的请求还没写完时不能换店铺（原来先读文件、后建任务，期间队列是空的，能换过去，会混进两个店铺）。
  - 店铺商品没扫全时，改专属号的预览如实写「没扫全」，不能确认修改；没填凭证时写「只查了本地」。
  - 队列里有这个店铺的图时不能改店铺缩写。
  - 「改专属号」按钮在队列清空后（这一批的图都「清除已完成」了）也显示，照样能改 CSV 里的行。
  - 遗留（没有自动测试，代码审查过）：改名中途失败的回滚、和单张图操作的互斥。
