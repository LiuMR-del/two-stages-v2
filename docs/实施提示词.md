你要在 `/Users/liu/Downloads/tool/Two stages-1/` 里从零实现「Two stages 重构版」。这是一个本机运行的主图批量生成工具：上传任意品类的竞品图后，自动识别品类、提取素材图、按该品类设定的模版生成主图，再识别场景、关键词和定制项，有定制项时生成定制空白图。

## 先读这三份文件

1. `docs/实施文档.md`：**按它实现**。里面有目录结构、数据结构、接口、调度算法、提示词原文、测试清单和里程碑。
2. `docs/重构方案.md`：需求背景和已经定下的决定。和实施文档有冲突时，以实施文档为准。
3. `docs/界面样例.html`：界面的视觉和交互标准。用浏览器打开看，也可以直接读源码，把里面的颜色变量和布局搬过来。

旧版代码在 `/Users/liu/Downloads/tool/Two stages/`，**只能用来查经验**（实施文档 §0 列出了值得看的文件），不要复制它的代码和结构。

## 工作方式

- 按实施文档 §12 的里程碑 M1 → M5 依次做。每个里程碑做到 `npm run typecheck` 和 `npm test` 全部通过后，再 `git commit`（第一次先 `git init`，并把 `data/`、`node_modules/` 写进 `.gitignore`），然后进入下一个。
- 测试一律用模拟中转站和临时目录，不能花真实额度，也不能动 `library/`、`data/` 里的真实数据。
- 文档里写清楚了的直接做，不用问我。遇到文档没写到、而且会影响结果的事，先问我，**一次只问一个问题**，用选项的形式给出你的推荐。
- 完成 M3 和 M5 时，用中文向我汇报一次：做了什么、测试结果（失败就原样贴出来）、还有什么没定。
- 到 M5 需要真实验收时，再向我要中转站的地址和 Key，以及真实的竞品图。
- 界面文字、错误提示、日志都用中文。代码注释只写代码本身表达不出来的约束。
- 必须同时支持 Mac 和 Windows：路径用 `path.join`，不依赖 shell 命令。

## 最重要的几条（实现时反复核对）

1. **图和提示词严格对应**：模版库配方卡的预览（`/library/recipe`）和流水线第 ③ 步共用同一个 `buildMainRequest`。界面上显示的「图 1、图 2」、前置句、提示词，必须和实际发出去的完全一致。
2. **状态流转只走白名单**：一张图失败只影响它自己；只有 401/403 才暂停对应那一类接口。
3. **队列随时能加图**：服务重启后从断点继续；「需处理」的图处理完之后挪到队尾。
4. **继承旧版的雷区**：实施文档 §13。
