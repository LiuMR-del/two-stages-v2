# Two stages 重构方案（v1 草案，2026-10-26）

在 `Two stages-1/` 下从零重写，不复用旧版代码。旧版的踩坑经验（见末尾）会继承。

## 1. 目标

上传任意品类的竞品图，工具会：

1. 自动识别品类和款式。
2. 按品类尺寸提取素材图。
3. 按该品类设定的模版生成主图。
4. 识别场景、关键词和可定制项。
5. 有定制项时生成定制空白图。

一批图里可以混着不同品类。队列运行中也能随时追加图片。认不出来的图会进异常区，不会卡住队列。

## 2. 已确认的决定

| 项 | 决定 |
|---|---|
| 运行形态 | 本机工具，浏览器操作，不连知识库平台 |
| 使用者 | 主要自己用，也会分给同事。做 Mac 和 Windows 两版双击启动。模版库放在工具文件夹里，复制文件夹就能带走 |
| AI 接口 | 都是 OpenAI 兼容的中转站。**生图**和**分析**各配一套地址、Key 和模型 |
| 模版形式 | 一段提示词，加一张可选的参考图。有图时，参考图、素材图、提示词一起发；没图时只发素材图和提示词 |
| 默认模版 | 「贴图」提示词，加该款式的白底图 |
| 模版选择 | 每个品类事先选好用默认模版还是某个自定义模版。运行时 AI 先认出品类，再调用该品类选中的模版 |
| 素材尺寸 | 每个款式配一个大致比例（如相框·横版 3:2）。用来给素材归类、方便印到主图上，不要求精确 |
| 未匹配品类 | 这张图挪到队尾，进异常区并附上原因。异常区里可以直接指定品类或款式、新建品类、重试或删除。处理完后它自动回到队列 |
| 人工把关 | 全自动跑完。之后可以挑单张，从任意一步重做，下游步骤会自动跟着重跑 |
| 初始数据 | 只预置「贴图」提示词和默认的提取提示词。品类、款式、白底图都在模版库页面里自己添加 |

## 3. 每张图的流水线

```
竞品图
 ① 路由识别（分析模型）  → 品类 / 款式 / 置信度 / 理由
      └ 未匹配或置信度低 → 异常区「未匹配品类」（附 AI 猜的品类名）
 ② 提取素材图（生图模型）  竞品图 + 提取提示词（代入品类、款式、比例），size 按款式比例
 ③ 生成主图（生图模型）   [模版参考图] + 素材图 + 模版提示词
 ④ 信息识别（分析模型）   主图 → 场景 / 关键词 / 可定制项 / 需留空项
 ⑤ 定制空白图（生图模型） 仅在 ④ 有需留空项时生成
```

- **① 路由识别**：发给模型的提示词里，会动态列出模版库中所有品类、款式和识别说明。模型必须从列表里选一项，或者返回「无匹配」，只能输出 JSON。
- **② 提取提示词**：全局有一段默认提示词，单个品类可以覆盖它。占位符有 `{品类}`、`{款式}`、`{比例}`。
- **③ 主图的 size**：有参考图时按参考图的宽高算，没有时按款式比例算。前置句里写的比例和 `size` 用同一组宽高算。
- **④ ⑤ 的逻辑**：沿用旧版，包括兜底词表、拦截词表、英文映射，以及空白图不做本地擦除。


```jsonc
    "activeTemplate": "default",         // "default" 或某个自定义模版 id
```

### 4.1 怎么保证图和提示词对应

1. **绑定写在数据结构里**：一张图片只属于一个「品类 × 款式 × 模版」组合。白底图挂在款式上，参考图挂在「模版 × 款式」上。运行时由代码按识别结果查表，不存在手动配对。
2. **顺序固定，并自动声明角色**：发送顺序固定为「白底图或参考图 → 素材图」，没上传的图不发。系统会在提示词最前面自动加一句「第一张是白底图，第二张是素材图」，编号随实际发送的张数变化。界面上显示的「图 1、图 2」与实际发送顺序完全一致。
3. **引用检查**：提示词里写了「第 N 张」，但这个款式实际发送的图少于 N 张时，模版库标黄提醒。
4. **完整性检查**：用默认模版的款式缺白底图时，品类列表会标出来。运行时遇到缺图的组合，图会转入「需处理」，绝不会缺图照发。
5. **快照可核对**：每张图开始生成主图时，记录实际发送的图片指纹和提示词全文。详情面板按同样的「图 1 + 图 2 + 提示词 → 结果」布局展示，可以逐张核对。

- 页面上可以增、删、改品类、款式和模版。白底图支持拖拽上传或替换。默认模版和提取提示词都能编辑。
- 提供导出和导入：把整个模版库打包成一个 zip 发给同事，导入时可以选「合并」或「覆盖」。
- 改模版不影响正在跑的图：每张图在进入 ② 时，会把当时用到的提示词和参考图快照下来。

## 5. 队列与任务

- **持久化**：每张图是一条任务记录，保存在 `data/tasks/*.json`，用原子写入。服务重启后，正在运行的步骤回到「待处理」，从断点继续。
- **追加图片**：拖拽、粘贴、选文件、选文件夹，随时都能加进队列，不区分批次，也不再限制 20 张。
- **并发**：生图槽位和分析槽位分开计数，默认分别是 2 和 3，都可以在设置里调。调度时先把排在前面的图推进完，再处理新加的图。
- **状态**：待处理 → ①…⑤ 进行中 → 完成；另有「异常」和「已停止」。状态判断全部用白名单。
- **异常区**：收集以下几类图，每张都写明原因，并给出对应的操作按钮：
  - 未匹配品类
  - 该品类没有白底图或模版
  - 重试 4 次仍失败
  - 内容被拒
- **重试**：沿用旧版做法，间隔 3、6、10、15 秒；中转站不支持保真参数时自动去掉。失败只影响这一张图，不会让整批暂停。
- **单张重做**：从 ①～⑤ 任意一步开始，可以临时改这一次的提示词，下游步骤自动跟着重跑。重做 ① 时，可以手动指定品类。

## 6. 界面

界面样例：`docs/界面样例.html`（直接用浏览器打开）。顶栏切换两个页面：**工作台**、**模版库**；右上角是设置抽屉。

**工作台**
- **导入区**：拖拽、粘贴、选择图片都可以，运行中也能继续加。
- 三个标签页：
  - **队列**：每张图一行，依次是竞品图、品类和模版标签、素材 → 主图 → 空白图三张缩略图、状态。
  - **需处理**：每张图写明原因，并直接给出处理按钮。
  - **识别信息**：场景、关键词、可定制项，每项都能一键复制，可以导出 CSV。
- 点任意缩略图，从右侧打开详情面板，按五步切换。每一步都按「图 1 + 图 2 + 提示词 → 结果」展示实际发出的内容，可以从这一步重做。

**模版库**
- 左边是品类列表，缺图的品类标点提醒。
- 右边依次是：品类名称、AI 识别说明、款式标签（附比例）、主图模版标签（标出「使用中」的那个）。
- 再往下是「发送给生图模型」配方卡和各款式的检查结果，最后是提取提示词：默认用全局，也可以本品类单独设置。

## 8. AI 调用与异常处理

### 8.1 分工

AI 只负责判断和出图。查模版、拼提示词、定图片顺序、校验结果、尺寸后处理、排队重试，全部由代码完成。

| 环节 | 模型 | 输入 | 输出 | 代码校验 |
|---|---|---|---|---|
| ① 识别品类 | 分析 | 竞品图，加上模版库清单（品类、款式、识别说明） | 品类、款式、置信度、理由、猜测的品类名 | 结果必须在清单里，且置信度不低于阈值（默认 0.7） |
| ② 提取素材 | 生图 | 竞品图 + 提取提示词 | 素材图 | 能解码；尺寸对齐款式比例 |
| ③ 生成主图 | 生图 | 白底图或参考图（可选）+ 素材图 + 模版提示词 | 主图 | 能解码；限制长边、补成方图、控制体积 |
| ④ 信息识别 | 分析 | 主图（压缩后） | 场景、关键词、可定制项、需留空项 | JSON 格式和字段校验；关键词去重；需留空项过兜底和拦截词表 |
| ⑤ 空白图 | 生图 | 主图 + 留空提示词 | 空白图 | 尺寸强制对齐主图 |

每张图调用 4～5 次 AI：分析 2 次，生图 2～3 次。

### 8.2 调用方式

两套接口都走 OpenAI 兼容的中转站，各配一套地址、Key 和模型。

**生图**：`POST /images/edits`，multipart 格式。
- 图片按固定顺序放进 `image[]`。
- `prompt` = 角色与画面比例前置句 + 模版提示词。
- `size` 按目标比例选三档之一：`1536x1024`、`1024x1536`、`1024x1024`，并与前置句用同一组宽高计算。
- 附带 `quality=high` 和 `input_fidelity=high`。
- 返回结果兼容 base64、URL、二进制三种形式。

**分析**：`POST /chat/completions`。
- system 消息写规则和 JSON 格式，user 消息放图片（长边 1536、JPEG，并控制字节数）。
- `temperature: 0`。
- 从回复中取第一个 JSON 块，再做格式校验。
- ① 的提示词每次按模版库现场生成。

**并发与超时**：生图默认 2 路、分析默认 3 路，两边分开计数。超时：生图 300 秒，分析 60 秒。

### 8.3 异常处理

| 情况 | 处理 |
|---|---|
| 网络错误、超时、5xx、返回的图片损坏 | 重试 4 次（间隔 3、6、10、15 秒），仍失败则这一张转「需处理 · 生成失败」 |
| 429 限流 | 按 `Retry-After` 等待，并临时降低并发 |
| 中转站不认 `quality` / `input_fidelity` | 去掉这两个参数立即重发，不计入重试次数，之后的请求都不再带 |
| 401/403 | 整个队列暂停，顶部提示配置错误；改好后自动继续 |
| 内容被拒 | 不重试，转「需处理 · 内容被拒」，可以改提示词后重做 |
| 分析结果不是合法 JSON 或缺字段 | 加强约束再问一次，仍不行转「需处理」 |
| 品类不在清单里或置信度低 | 转「需处理 · 没找到对应品类」，附 AI 猜测的品类名 |
| 缺白底图 | 不调用 AI，直接转「需处理」，补图后自动回到队列 |

## 9. 技术架构

### 9.1 总体

本机运行一个 Node 进程，同时提供网页和接口，浏览器访问 `http://127.0.0.1:3311`。整套工具没有数据库、没有云端，唯一的原生依赖是 sharp（有预编译包，Mac 和 Windows 都能直接装）。

```
浏览器（Vue 3 单页）
   │  REST：增删改    SSE：实时进度
   ▼
Node 服务（Express + TypeScript）
   ├ api/        路由层：jobs / library / settings / events / files
   ├ scheduler/  调度器：任务队列 + 生图、分析两组槽位
   ├ pipeline/   五个步骤处理器：组装请求 → 调用 AI → 校验 → 落盘
   ├ prompts/    提示词组装：路由清单、前置句、信息识别、留空
   ├ ai/         两个客户端：重试、错误分类、参数降级、限流
   ├ library/    模版库读写、完整性与引用检查、导入导出 zip
   ├ store/      任务和设置的 JSON 存储（原子写入）
   └ image/      sharp 工具：比例、size、压缩、裁剪、补白、对齐尺寸
   │
   ├─ library/   模版库（随工具文件夹走，可分享）
   ├─ data/      本机数据：任务、设置（含 Key）、导入原图缓存
   └─ ~/Downloads/主图生成/   输出
```

### 9.2 关键设计

- **任务即状态机**：每张图对应一条记录。
  - 包含：`id`、原图、`route`（品类 / 款式 / 置信度）、`steps[5]`、`info`。
  - `steps[5]` 的每一步记录：`state`、`attempts`、`error`、`snapshot`（实际发送的图片指纹和提示词）、`output`。
  - 状态只能沿白名单流转。每次变更先写盘，再通过 SSE 推给页面。
- **调度器是事件驱动的**：新任务加入、某个槽位空出来、某一步完成，都会触发一次扫描。扫描按队列顺序，找第一个「当前能跑、且对应槽位有空」的步骤。所以新加的图不会打断正在跑的图，也不会被前面的图卡住。
- **重启续跑**：服务启动时，把所有「进行中」的步骤改回「待处理」，然后接着调度。
- **步骤处理器互相独立**：每一步只读前一步的产出，只写自己的产出。重做第 N 步时，清掉 N 及之后各步的产出，再重新排队。
- **模版库与本机数据分开**：`library/` 可以导出给同事；`data/` 里的 Key、任务记录只留在本机。Key 存在后端的 `data/settings.json`，不放在浏览器里。
- **前端只做展示**：界面不保存业务状态。页面刷新或关闭再打开，从服务端恢复。
- **自动退出**：队列不为空时一直运行。队列空闲并且没有页面打开超过 10 分钟后，服务退出。

### 9.3 技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node 22 LTS | 和旧版一致，sharp 生态成熟 |
| 后端 | Express + TypeScript（`zod` 校验输入与 AI 输出） | 简单；类型和运行时校验可以用同一份定义 |
| 前端 | Vue 3 + Vite + Pinia | 组件化，取代旧版 2000 多行的单个 HTML |
| 图片 | sharp | 唯一原生依赖，有预编译包 |
| 存储 | JSON 文件 + 按 sha256 命名的图片 | 免数据库，可直接复制分享 |
| 测试 | vitest + mock 中转站（可模拟成功、失败、无匹配、拒绝、限流、坏 JSON） | 不花真实额度也能跑完整流程 |

### 9.4 目录与分发

```
Two stages-1/
  server/        后端源码（TS）
  web/           前端源码（Vue）
  dist/          构建产物（server.js + 静态页），随工具分发
  library/       模版库
  data/          本机数据（不分发）
  scripts/       mock-relay.ts、build 脚本
  双击启动.command / 双击启动.bat

```

启动脚本依次做五件事：检查 Node 版本、首次运行时安装依赖（只装生产依赖）、启动 `dist/server.js`、打开浏览器、端口被占用时自动换一个。同事拿到后不需要构建。之后如果不想让同事装 Node，可以把便携版 Node 一起打包。

## 11. 继承旧版的经验

- 提取用的前置句里禁止出现「铺满画布」这类措辞，否则会丢内容。
- 前置句写的比例和 `size` 必须用同一组宽高算。
- 送去识别的图要按字节数压缩，避免请求体过大被网关拦截。
- 状态判断全部用白名单。
- 「补成方图」改成只加白边、图案像素保持原样（旧版是先放大再补白）。
