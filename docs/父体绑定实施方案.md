# 父体绑定实施方案

给每张图从飞书「父体分类汇总」表里找一个合适的父体，再用店铺 SP-API 推算下一个变体名，结果放进「识别信息」。本文是实施依据，和 `实施文档.md` 冲突时以本文为准。

---

## 一、已经定下的事

| 事项 | 决定 |
| --- | --- |
| 开关 | 设置里「识别父体」开关，**默认关闭**。关闭时第 6 步直接跳过，不读飞书、不调 SP-API、不花分析额度，界面和 CSV 里也不出现父体相关内容 |
| 飞书怎么读 | ~~用户用自己的飞书账号授权一次（OAuth，user_access_token）~~ **2026-10-27 改为应用身份（tenant_access_token）**：只用 App ID / App Secret 读链接，不用登录、不会过期；父体表要在飞书里「添加文档应用」给这个应用阅读权限（见第十一节）。仍复用 lark-mcp 已在用的那个自建应用 |
| 链接 | 填在设置里，随时可换；用过的链接留在列表里，下次直接选（最多 10 条） |
| 什么时候读表 | 不定时同步。任务跑到第 6 步时现读；同一个链接 5 分钟内读过的结果共用，避免一批图读几十次 |
| 表的结构 | 一个品类一个标签页；按表头名字认列：`主题`、`父体SKU`、`父体ASIN`，其他列忽略，列的顺序变了也没关系 |
| 品类 ↔ 标签页 | 模版库每个品类加「对应标签页」，默认同名（如 铝板画 → 铝板画），名字不同时手动选（相框 → 帆布画，花园灯 → 庭院灯） |
| 匹配看什么 | 竞品图 + 第 4 步识别出的场景、关键词，对照这个标签页里每一行的主题和父体 SKU |
| 命名规则 | 读父体所有子体的变体属性值，归类成命名方式（Design 01～04 算一种「Design ##」），数量最多的那种往下排一个号，位数不变 |
| 同一批里的占号 | 队列里已经分到同一父体、同一命名方式的号也算占用，依次往后排（Design 05、06、07） |
| 子 SKU | 不推荐。实测同一个父体下子 SKU 前缀不统一（`…6709223xx` 和 `…6709233xx` 混用，Dumpling 下还有 `HJ-cn-tcgs…`） |
| 拿不准 | 把握低于阈值（默认 0.7，设置里可改）标「待确认」，不进「需处理」，不挡队列 |
| 复制按钮 | 父体 SKU、下一个变体名各一个，识别信息表和详情里都有 |
| 没有合适的父体 | 2026-10-27 新增：AI 判断表里没有合适的父体时，按同一标签页的命名方式建议一个新父体 SKU（见 4.2），子体从 `Design 01` 起，状态「建议新建」。只给建议，不去飞书或店铺里创建。「待确认」不附带新建建议 |

实测依据（2026-10-27，只读）：

- `HJ-cn-yklgj-Christmas Baby`：Design 01～04 → 下一个 Design 05
- `HJ-cn-yklgj-Christmas`：Design 01～05 → Design 06
- `HJ-cn-yklgj5-Christmas Dumpling`：Design 02、03 + Ceramic → 「Design ##」2 个最多 → Design 04

## 二、数据

### 2.1 设置 `data/settings.json` 新增 `parent`

```ts
parent: {
  enabled: boolean                    // 「识别父体」开关，默认 false
  sheetUrl: string                    // 当前使用的链接
  recentUrls: { url: string; title: string; usedAt: string }[]   // 最多 10 条，title 是表格名
  threshold: number                   // 默认 0.7
  creatorMark: string                 // 新建父体 SKU 里的创建人标识，默认 '5'（见 4.2）
  feishu: {
    appId: string
    appSecret: string                 // 打码显示
    user: string | null               // 授权人的飞书名字，显示用
    accessToken: string; accessExpiresAt: string
    refreshToken: string; refreshExpiresAt: string   // 有效期以每次接口返回为准，不写死
  }
  spapi: {
    sellerId: string
    clientId: string; clientSecret: string; refreshToken: string   // 打码显示
    marketplaceId: string             // 默认 ATVPDKIKX0DER（美国）
    endpoint: string                  // 默认 https://sellingpartnerapi-na.amazon.com
  }
}
```

- 所有密钥、token 都走 `registerSecret`，日志里不出现；接口返回时打码。
- 「从文件导入」：上传那份 RTF（或粘贴文字），按正则取出店铺 ID、Client ID、Client Secret、Refresh Token，不依赖 macOS 的 textutil，Windows 也能用。

### 2.2 模版库：品类加一个字段

```ts
Category.parentTab: string | null     // null = 用和品类同名的标签页
```

用 zod 默认值 `null`，旧库直接能读，不升版本；导出、导入的 zip 会带上它。

### 2.3 任务

- `STEP_COUNT` 改成 6，`STEP_NAMES` 加「匹配父体」，`kindOf(5) = 'analysis'`（占分析并发）。
- `attention.step` 上限改成 5。
- 新增 `job.parent`：

```ts
parent: null | {
  status: 'matched' | 'unsure' | 'none' | 'new'   // new = 建议新建父体（见 4.2）
  message: string | null              // none / unsure 的原因，如「飞书表里没有『车库横幅』标签页」
  tab: string; readAt: string         // 读的是哪个标签页、几点读的
  sku: string | null; asin: string | null; theme: string | null
  confidence: number | null; reason: string | null; manual: boolean
  candidates: { sku: string; asin: string; theme: string; confidence: number | null }[]   // 最多 3 个
  naming: null | {
    attribute: string                 // 如 color
    existing: string[]                // 现有子体的值
    groups: { pattern: string; count: number }[]   // 如 [{ 'Design ##', 2 }, { 'Ceramic', 1 }]
    next: string | null               // null = 最多的那种命名没有编号，要手动起名
    note: string | null
  }
  proposal: null | {                  // 只有 status = 'new' 时有值；sku / theme 同时写进上面的 sku、theme，naming.next = 'Design 01' 起
    sku: string                       // 如 HJ-cn-yklgj5-Snowman
    prefix: string                    // 如 HJ-cn-yklgj5
    theme: string
    basedOn: string[]                 // 参照的表里 SKU，最多 5 个，显示用
    themeCandidates: string[]         // AI 给的候选，按顺序试过的
  }
}
```

- 旧任务（5 步）读入时补一条第 6 步，状态 `skipped`，`parent` 为 null；需要的话在详情里对第 6 步点重做。

## 三、飞书

### 3.1 授权

1. 设置里填 App ID、App Secret，点「授权飞书」。
2. 浏览器打开 `https://accounts.feishu.cn/open-apis/authen/v1/authorize`，scope 是 `wiki:wiki:readonly sheets:spreadsheet:readonly offline_access`。浏览器已登录飞书时，点「授权」即可，不用扫码。
3. 回调到本机服务，用 code 换 token（`/open-apis/authen/v2/oauth/token`），保存 access / refresh token 和有效期，页面显示「已授权（名字）」。
4. 每次用之前检查 access token，过期就用 refresh token 换新的，并**保存新的 refresh token**（旧的会作废）。
5. refresh token 也过期时（飞书文档的示例是 7 天，以接口返回为准），第 6 步整体暂停，顶栏提示「飞书授权已过期，去设置重新授权」，授权后自动继续。

回调地址：先确认这个应用在开发者后台「安全设置 → 重定向 URL」里登记了哪些地址。如果已经有 lark-mcp 用的 `http://localhost:3000/callback`，授权时临时在 3000 端口接收一次，用户不用改后台；否则请用户登记一条 `http://127.0.0.1:3311/api/feishu/callback`。服务没跑在 3311 时（端口被占），授权页会显示要登记的实际地址。

### 3.2 读表

- 链接解析：`/wiki/<token>` 先调 `wiki/v2/spaces/get_node` 换成表格 token；`/sheets/<token>` 直接用。链接里的 `?sheet=` 忽略，所有标签页都读。
- 标签页列表：`sheets/v3/spreadsheets/<token>/sheets/query`。
- 内容：只读当前品类对应的那一页，`sheets/v2/.../values/<sheetId>!A1:Z1000`。
- 表头：在前 5 行里找含「父体SKU」的那一行当表头；父体 SKU 为空的行跳过；同一页里 SKU 重复的只留第一条。
- 缓存：同一个链接 + 标签页，5 分钟内共用；正在读的请求也共用，不会同时发多次。
- 设置里「读一下试试」：显示表格名、所有标签页和每页的父体数量，顺便刷新模版库里「对应标签页」的下拉选项。

## 四、SP-API

- 换 token：`POST https://api.amazon.com/auth/o2/token`（refresh_token），access token 缓存到过期前 1 分钟。
- 父体：`GET /listings/2021-08-01/items/{sellerId}/{父体SKU}?includedData=summaries,relationships` 拿 ASIN 和变体主题属性（如 `color`）。
- 子体：`GET /listings/2021-08-01/items/{sellerId}?variationParentSku=…&includedData=summaries,attributes&pageSize=20`，按 `pageToken` 翻完所有页。不同状态（含未完成）的子体都算，避免撞名。
- 每次跑第 6 步都现查，不缓存，保证刚上架的子体能算进去。
- 429 按 `Retry-After` 等待重试；401 / 403 第 6 步整体暂停，提示去设置检查凭证。

### 4.1 命名推算 `pipeline/naming.ts`

1. 取变体主题里的属性。有多个属性时（如尺寸 + 颜色），选「带编号的值」占比最高的那个。
2. 每个值用 `/^(.*?)(\d+)\s*$/` 拆成前缀 + 编号，归类键是「前缀 + 编号位数」，显示成 `Design ##`；没有编号的值，值本身就是一类（如 `Ceramic`）。
3. 取数量最多的一类；数量一样时，取最大编号更大的那一类。
4. 最多的那类没有编号时，`next = null`，提示「这个父体的命名没有编号，请手动起名」，并列出现有名字。
5. 下一个号 = max（这一类现有最大编号，队列里其他任务已分到的同父体同命名方式的号）+ 1，补零到这一类最常见的位数。
6. 父体还没有子体：`next = 'Design 01'`，注明「这个父体还没有子体，按 Design 01 起」。

占号：分号在同一个父体 SKU 的互斥锁里进行，分到后写进任务，之后不变。任务删除、清除，或第 6 步重做换了父体，就释放这个号。

### 4.2 建议新建父体 `pipeline/newParent.ts`（2026-10-27 新增）

用户要求：表里没有合适的父体时，按表里同品类的命名方式起一个新父体，主题跟着图变。例子：毛毯 `HJ-mtfl5-Love`（HJ 店铺、mtfl 材质缩写、5 创建人标识、Love 主题），亚克力挂件 `HJ-cn-yklgj-Christmas`（cn 表示中国发货）。

1. **前缀**：对当前标签页的每一行，父体 SKU 以 `-主题` 结尾（大小写不敏感）时，去掉这段剩下的就是前缀；不以主题结尾的行跳过。统计前缀出现次数，取最多的；一样多时取表里靠后（较新）的那个。没有任何一行能拆出前缀 → 不建议，status `none`，message「表里的父体 SKU 看不出命名规则，没法建议新父体」。
2. **创建人标识**：前缀最后一段末尾的数字换成设置里的 `creatorMark`（默认 `5`），没有数字就补上。`HJ-cn-yklgj` → `HJ-cn-yklgj5`，`HJ-cn-yklgj3` → `HJ-cn-yklgj5`，`HJ-mtfl` → `HJ-mtfl5`。
3. **主题**：第 6 步的匹配请求里同时要求模型在 `pick` 为 null 时给 `new_themes`：2～3 个英文主题，1～3 个词、每个词首字母大写，风格照着这个标签页里已有的主题列（提示词里带上表里的主题样例）。去掉 SKU 里不能用的字符，空格保留（表里已有带空格的，如 `Christmas Baby`）。
4. **查重**：`前缀-主题` 依次和表里所有父体 SKU（大小写不敏感）比对，再用 SP-API `GET /listings/.../items/{sellerId}/{sku}` 只读查一次（404 = 没占用）。重名换下一个候选；都重名 → status `unsure`，message「建议的父体 SKU 都已存在：……，请手动起名」。
5. **同一批共用**：队列里别的任务已经建议了同一个新父体 SKU（同前缀同主题）时直接共用，子体按 4.1 的占号依次排 `Design 01`、`02`……；占号锁按这个新 SKU 加。
6. 结果：status `new`，`naming.next` 按 4.1 第 6 条从 `Design 01` 起，`naming.note`「这是建议新建的父体，飞书表和店铺里都还没有，需要你手动创建」。

## 五、第 6 步「匹配父体」 `pipeline/step5Parent.ts`

1. 开关关着 → 步骤直接 `skipped`（不占并发），详情里显示「识别父体没有打开，可以在设置里打开」。开关开着但缺链接、飞书授权或 SP-API 凭证 → 同样 `skipped`，写明缺哪一项。
2. 按品类的 `parentTab`（或同名）找标签页；找不到 → `done`，status `none`，提示去模版库选对应标签页。
3. 标签页里没有父体 → `none`。
4. 让分析模型看竞品图（缩小后的 JPEG）+ 品类 + 场景 + 关键词 + 候选列表（编号、主题、父体 SKU），只输出 JSON：

   ```json
   { "pick": 编号或 null, "confidence": 0~1, "reason": "一句话", "alternatives": [编号, 编号], "new_themes": ["pick 为 null 时给 2~3 个英文主题，否则空数组"] }
   ```

   用编号而不是让模型抄 SKU，避免编出不存在的 SKU。`pick` 为 null → 按 4.2 建议新建父体（status `new`），拆不出前缀时才是 `none`。快照照常记录，详情里能看到实际发送的内容。
5. 用选中的父体查 SP-API、推算命名。店铺里查不到这个父体 SKU → status `unsure`，提示「店铺里查不到这个父体 SKU，检查飞书表里的 SKU 是否写对」。
6. 把握 ≥ 阈值且命名算出来了 → `matched`，否则 `unsure`。
7. 完成后重写这一批文件夹里的识别信息 CSV（和第 4 步一样）。

重做：

- 详情里点候选、或搜索手动选父体：`POST /jobs/:id/parent { sku }`，只重算命名，标 `manual`。
- 「重新匹配」：普通的重做第 6 步，重新读表、重新问 AI。
- 重做前面任何一步，第 6 步会跟着重跑（现有 `resetFrom` 的逻辑）。

调度：第 6 步排在空白图后面（现有步骤是顺序执行的），占分析并发。飞书、SP-API 的授权问题用单独的暂停标记，只停第 6 步，不影响前 5 步。

## 六、出错时怎么办

| 情况 | 结果 |
| --- | --- |
| 开关关着 | 第 6 步跳过，任务照常「完成」，不发任何请求 |
| 开关开着但缺链接、授权或 SP-API | 第 6 步跳过，写明缺哪一项 |
| 飞书授权过期 / 被撤销、SP-API 凭证错 | 所有任务的第 6 步暂停，顶栏提示，处理后自动继续 |
| 链接打不开、没有权限 | 同上暂停，提示「这个链接读不了：……」 |
| 品类没有对应标签页、标签页是空的 | 完成，状态「没有合适的父体」，可手动选 |
| AI 认为都不合适 | 完成，状态「建议新建」（4.2）；表里的 SKU 拆不出前缀时是「没有合适的父体」；建议的 SKU 都已存在时是「待确认」 |
| 店铺里查不到父体 SKU、命名没有编号 | 完成，状态「待确认」，写明原因 |
| AI 或网络出错 | 按现有规则重试；最终失败进「需处理」，可以点重试 |
| SP-API 429 | 等待后继续，不算重试次数 |

## 七、接口

| 接口 | 说明 |
| --- | --- |
| `POST /settings/feishu/authorize` | 返回授权页地址，前端打开 |
| `GET /api/feishu/callback`（或临时 3000 端口） | 换 token，完成后显示「授权成功，可以关闭这个页面」 |
| `POST /settings/feishu/logout` | 清掉 token |
| `POST /settings/parent/test` | 读一次当前链接，返回表格名、标签页和父体数量 |
| `POST /settings/spapi/import` | 上传 RTF 或文字，取出凭证（不回显明文） |
| `POST /settings/spapi/test` | 换 token 并查一次店铺，返回是否成功 |
| `GET /parent/rows?tab=` | 手动选父体时搜索用，返回这一页（或所有页）的父体 |
| `POST /jobs/:id/parent` | `{ sku }` 手动指定父体 |
| `POST /jobs/:id/redo` | `step: 5` 重新匹配 |

## 八、界面

按已经确认的样例图做：

- **开关**：设置「父体匹配」一组最上面是「识别父体」开关（默认关）。关着时这组其他设置折叠起来；打开时如果缺链接、授权或 SP-API 凭证，开关下面直接列出还缺什么。
  - 打开不会给已经完成的图补匹配，需要的话在详情里对第 6 步点「重新匹配」。
  - 关掉后，还没跑到第 6 步的图到那一步会直接跳过；已经匹配好的结果保留。
  - 开关关着、而且队列里没有任何图带父体结果时，识别信息表不显示「父体」「下一个变体名」两列，导出的 CSV 也不带父体列；详情里第 6 步标签照常显示，内容是「识别父体没有打开」。

- **识别信息表**：加「父体」列（父体 SKU + 复制，下一行小字是主题 · ASIN）和「下一个变体名」列（变体名 + 复制，旁边是把握或「待确认」）。没有合适的父体时显示原因和「手动选」。「建议新建」时父体列显示建议的 SKU + 复制，标一个「建议新建」标签（和「待确认」区分颜色），小字是主题 ·「需手动创建」；变体名列是 `Design 01` 起 + 复制。
- **详情第 6 步（建议新建）**：显示建议的 SKU、前缀、主题、参照的表里 SKU、试过的主题候选，提示「飞书表和店铺里都还没有，需要你手动创建」；仍可「搜索别的父体」手动改成已有父体。
- **详情第 6 步**：候选列表（主题、SKU、把握，可点选切换）；命名卡片（父体 ASIN、变体属性、现有子体、各命名方式数量、推荐名标虚线框）；父体 SKU 和推荐变体名各一个复制按钮；「搜索别的父体」「重新匹配」。
- **设置「父体匹配」**：飞书（App ID / Secret、授权状态和按钮、链接输入框 + 用过的链接下拉、读一下试试）；SP-API（从文件导入、四项打码显示、站点、测试连接）；把握阈值。
- **模版库品类**：「父体表标签页」下拉，默认「同名（xxx）」，选项来自最近一次读表；没读过时提示先去设置里读一下。
- **导出 CSV** 加列：父体主题、父体SKU、父体ASIN、建议变体名、父体把握、父体状态（建议新建时 ASIN 为空，状态写「建议新建」）。
- **设置**：把握阈值下面加「创建人标识」，默认 `5`。

## 十一、变更记录

### 2026-10-27 · 第一段「设置和凭证」

- **飞书回调**：用户确认应用后台登记了 lark-mcp 用的 `http://localhost:3000/callback`。默认 `parent.feishu.redirect = 'lark3000'`：点「授权飞书」时临时在本机 3000 端口（127.0.0.1 和 ::1）接收一次回调，收到后或 10 分钟后关掉；3000 端口被占用时提示「可能 lark-mcp 正在登录」。另一种 `self`（回调进本服务 `/api/feishu/callback`）保留作备用、测试用。原文 3.1 写的 `127.0.0.1:3311` 不对：用户日常的服务跑在 3451，用 `self` 时授权页里给的是实际端口。
- **设置新增 `parent.tabs`**：「读一下试试」读到的标签页名存下来，第四段模版库「对应标签页」下拉直接用，不用每次读表。
- **接口地址的隐藏字段**：`parent.feishu.baseUrl / accountsUrl`、`parent.spapi.endpoint / tokenUrl`，测试时指向 `scripts/mock-parent.ts`（挂在模拟中转站上）。
- **凭证导入**：RTF 里只有「店铺ID」有标签，Client ID、Client Secret、Refresh Token 没有标签，按格式认（`amzn1.application-oa2-client.`、`amzn1.oa2-cs.v1.`、`Atzr|`）。RTF 按文件声明的代码页（936 = GBK）解码，不依赖 textutil。
- **打码**：店铺 ID、Client ID 也和 Secret 一样只露末 4 位（实施提示词「四项打码显示」）；它们同样登记进日志打码。
- **SP-API 测试连接**：换 token 后按卖家搜一条商品（`GET /listings/2021-08-01/items/{sellerId}?pageSize=1`）。access token 缓存按全部凭证区分，改了任何一项都会重新换。
- **审查后补的规则**（2026-10-27）：
  - 所有会改东西的接口（POST / PUT / PATCH / DELETE）都要同源：带了别的 `Origin` 一律 403。否则别的网页能借用户的浏览器提交表单，换掉 SP-API 凭证、退出飞书授权。
  - 接口地址（`feishu.baseUrl / accountsUrl`、`spapi.endpoint / tokenUrl`）设置接口改不了，只能程序内部设；否则改了地址就能把 token 和 Client Secret 发到别处。
  - 改 App ID 不清授权（边打字边自动保存会误清），改为记下授权时的 `authAppId`，和现在的 App ID 不一样时界面提示「App ID 换过了，请重新授权」，第 6 步也当作授权失效。
  - 只有飞书明确返回 token 无效的错误码时才算授权过期，并在设置里标记（界面显示「已过期」）；超时、连不上按普通错误处理。飞书说 access token 无效但 refresh token 还有效时，先强制换一次再重试一次。
  - 「读一下试试」只读一次表信息；不是普通表格的页（多维表格等）跳过；某一页读不了只标在那一页。
  - 凭证导入没有「店铺ID」标签时才按格式兜底，排除站点 ID 和 AWS 访问密钥，候选不止一个就不猜。
  - 借用 3000 端口时，`::1` 被占用也报「端口被占用」（只有本机没有 IPv6 才忽略）。授权页先同步开窗口，被拦时界面给一个可以点的链接；切回工具窗口时自动刷新设置。
- **授权页在飞书 App 里打开**（2026-10-27 用户反馈「浏览器里登录太麻烦，打开的飞书 App 不能直接用吗」）：
  - 飞书客户端不对外提供登录状态，读它的本地数据不稳定也有安全风险，不做；用应用身份读表（不用登录，但每张表要给应用加权限）用户没选；复用 lark-mcp 的登录凭证实施提示词禁止。
  - 保留一次性授权，默认用 AppLink（`https://applink.feishu.cn/client/web_url/open?mode=window&url=<授权页>`）在已登录的飞书 App 里打开授权页，点「授权」即可，不用扫码；之后自动续期。打不开时界面上可以改用浏览器授权。
  - 飞书 App 内置浏览器能不能回调到 `http://localhost:3000/callback` 要实测确认。
- **改为应用身份读表，去掉用户授权**（2026-10-27 用户实测后决定）：
  - 原因：在飞书 App 里点授权报 20029「重定向 URL 有误」，应用后台并没有登记 `http://localhost:3000/callback`；用户觉得「我只是需要的时候读一下链接」，授权流程太麻烦。
  - 做法：`POST /open-apis/auth/v3/tenant_access_token/internal` 用 App ID / App Secret 换应用 token（内存缓存到过期前 1 分钟，飞书说 token 无效时重新换一次），读表的接口不变。
  - 代价：每张父体表要在飞书里「…」→「更多」→「添加文档应用」加一次这个应用；没加时提示这句话。应用没开通读表格 / 知识库权限时提示去开发者后台开通并发布。
  - 去掉：授权按钮、3000 端口临时回调、`/settings/feishu/authorize`、`/api/feishu/callback`、`/settings/feishu/logout`，设置里的 user / token / redirect / accountsUrl 字段（旧设置文件里有也能读，保存时丢掉）。3.1 节作废。
  - App Secret、店铺 ID 输入框改成密码框（用户截图里露出了明文）。

- **流程**（`pipeline/step5Parent.ts`、`parent/match.ts`）：读品类对应标签页 → 让分析模型看竞品图 + 品类 + 场景 + 关键词 + 编号清单（最多 300 个）挑父体 → 查店铺、推算命名 → 在父体 SKU 的锁里算队列里已占的号并立即写进任务。`pick` 为 null 时按 4.2 建议新建（同一批共用同一个新 SKU，占号锁按新 SKU 加）。
- **4.2 补的规则**：实测表里「主题」列是中文（圣诞节婴儿），SKU 末尾是英文（…-Christmas Baby），按「SKU 以 -主题 结尾」一行都拆不出前缀。改为：先按原规则拆，拆不出时按最后一个「-」拆；给模型参考的主题样例也取 SKU 末尾的英文。

- **接口**：`POST /jobs/:id/parent { sku }` 手动指定（只重算命名、标 manual；不先释放原来的号，排号时本来就不算自己，失败就什么都不改。审查发现先释放再查店铺，查询失败写回时原来的号可能已被别的图拿走，两张图同号）；`POST /jobs/:id/redo { step: 5 }` 重新匹配；`GET /parent/rows?tab=` 搜索用。
- **释放号**：号是按队列里任务当前的 `parent` 现算的，任务删除 / 清空、第 6 步重做（`resetFrom` 清空 `parent`）、手动换父体后自然释放。
- 界面这一段只做了最少的：详情第 6 步显示结果、重做按钮叫「重新匹配」，顶栏显示第 6 步暂停原因；识别信息表、候选切换、复制按钮、搜索、模版库标签页下拉、CSV 列在第四段。
- **审查后补的规则**（2026-10-27）：
  - 第 6 步要串行发好几个请求（读表、问 AI、查父体、查子体、新建时逐个查重），每个请求单独计重试次数；原来共用一个上限，前面成功的请求也计数，后面一次超时就直接失败。
  - 开关关着 / 缺设置时，第 6 步的跳过不受分析接口 401 暂停影响。
  - 手动换父体：查飞书和店铺期间不占着这张图（删除、清空队列照常）；写入时这张图已经不在、或第 6 步正在重跑，就放弃这次结果并提示。
  - AI 说没有合适的父体却没给新主题：状态「没有合适的父体」，提示手动选或重新匹配。
  - 建议新建父体时，前缀统计和查重用表里所有父体，不只是给 AI 的前 300 个。
  - SP-API 返回 400 这类请求错误不重试，直接进「需处理」。
  - 飞书权限问题的暂停提示里写明「在飞书里处理好后，到设置里点『读一下试试』就会继续」；第 6 步暂停期间详情里显示暂停原因。
