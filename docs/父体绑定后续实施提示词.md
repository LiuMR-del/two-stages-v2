## 五、工作方式和规矩（必须遵守）

- 每段做完：`npm run typecheck` 和 `npm test` 全过 → `npm run build` → `git add -A -- . ':!library'`（**不要提交 `library/`，那是用户的真实模版库**）→ 提交，提交信息末尾加 `Co-Authored-By` 行（按你的工具约定）。
- 改了规则就在 `docs/父体绑定实施方案.md` 第十一节追加一条，写日期和原因。
- 重启 3451：先 `curl -s http://127.0.0.1:3451/api/jobs` 确认没有 running / queued 的图，再 `kill` 掉 `data/server.json` 里的 pid，用 `TS_PORT=3451 TS_NO_BROWSER=1 nohup node dist/server.cjs > /dev/null 2>&1 &` 启动。
- 自动测试只用模拟服务：`scripts/mock-relay.ts` + `scripts/mock-parent.ts`（`mock.parent.feishu / spapi` 可直接改数据；`mock.script({ parent: [...] })` 控制 AI 挑父体的回复）。第 6 步的端到端写法参考 `tests/e2e/parent.test.ts`（进程内服务，接口地址用 `ctx.settings.updateParent` 指到模拟服务——设置接口故意改不了这些地址）。**不要往 `~/Downloads` 写东西，不要动 `library/`、`data/` 里的真实数据。**
- **凭证安全**：任何时候不要把飞书 App Secret、SP-API 店铺 ID / Client ID / Secret / Refresh Token 打印到终端、日志、测试快照或回复里。对 SP-API、飞书只读，不调用任何修改接口。
- 所有会改东西的接口已经有同源检查（`sameOriginGuard`），新接口自动生效，不要绕开。
- 界面文字、错误提示、日志用中文；代码注释只写代码表达不出来的约束；Mac 和 Windows 都要能用（`path.join`）。
- 文档没写到、又会影响结果的事，先问用户，一次只问一个问题，用选项给出推荐。
